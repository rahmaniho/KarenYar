# امضای Release و انتشار حساب‌یار در بازار

خطای «بسته نباید با کلید دیباگ امضا شده باشد» به **امضای اندروید** مربوط است، نه لایسنس Pro یا Pro+ داخل برنامه. برای بازار، فایل **`app-release.apk` با امضای خصوصی Release** لازم است. تغییر نام `app-debug.apk` به Release مشکل را حل نمی‌کند.

> اگر این برنامه قبلاً منتشر شده است، از **همان Keystore و همان کلید قبلی** استفاده کنید. کلید جدید نمی‌تواند به‌روزرسانی نسخه‌ای با امضای متفاوت باشد. Keystore و رمزهای آن را در Git یا چت ارسال نکنید و نسخهٔ پشتیبان امن نگه دارید.

## روش اول: GitHub Actions، بدون نصب ابزارهای اندروید

### ۱. کلید امضای خودتان را آماده کنید

از Keystore انتشار قبلی استفاده کنید. فقط اگر اولین انتشار است و کلیدی ندارید، می‌توانید در Android Studio از **Build → Generate Signed App Bundle / APK → APK → Create new** کلید انتشار بسازید. از `debug.keystore` یا کلیدی با گواهی `Android Debug` استفاده نکنید.

### ۲. چهار Secret مخزن را تنظیم کنید

در مخزن گیت‌هاب به مسیر **Settings → Secrets and variables → Actions → New repository secret** بروید:

| نام Secret                  | مقدار                                                           |
| --------------------------- | --------------------------------------------------------------- |
| `ANDROID_KEYSTORE_BASE64`   | محتوای کامل فایل Keystore به‌شکل Base64؛ نه مسیر یا نام فایل    |
| `ANDROID_KEYSTORE_PASSWORD` | رمز بازکردن Keystore                                            |
| `ANDROID_KEY_ALIAS`         | نام دقیق کلید داخل Keystore                                     |
| `ANDROID_KEY_PASSWORD`      | رمز همان کلید؛ اگر با رمز Keystore یکسان انتخاب شده، همان مقدار |

برای تبدیل Keystore به Base64 روی Linux/macOS:

```bash
base64 < /path/to/karensoft-release.jks | tr -d '\n'
```

روی Windows PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\secure\karensoft-release.jks"))
```

خروجی Base64 هم حاوی کلید خصوصی رمزگذاری‌شده است؛ آن را فقط در Secret مربوط قرار دهید، نه در سورس، Issue، لاگ عمومی یا چت. رمزها را به‌صورت متن اصلی خودشان در Secrets بگذارید، نه Base64.

### ۳. خروجی Release بگیرید

1. به **Actions → Build Android APK → Run workflow** بروید.
2. شاخه‌ای را انتخاب کنید که تنظیمات جدید انتشار در آن قرار دارد.
3. در **`build_type`، گزینهٔ `signed-release`** را انتخاب کنید. پیش‌فرض فعلی `github-test` برای انتشار آزمایشی است و مناسب بازار نیست.
4. بعد از موفقیت اجرا، Artifact با نام **`hesabyar-android-release`** را دانلود و از حالت ZIP خارج کنید.
5. فایل **`app-release.apk`** را در پنل توسعه‌دهندگان بازار بارگذاری کنید. فایل `app-release.aab` نیز برای مسیرهای انتشار نیازمند AAB در همان Artifact موجود است.

فرایند ساخت، وجود هر چهار Secret را پیش از ساخت کنترل می‌کند. پیش از آپلود خروجی نیز امضای واقعی APK، نداشتن گواهی استاندارد Android Debug و نبودن پرچم `debuggable` بررسی می‌شود. اگر هر بررسی شکست بخورد، خروجی انتشار تحویل داده نمی‌شود؛ جایگزین Debug هم ساخته نمی‌شود.

تگ‌های نسخه (`v*`) نیز همین مسیر Release امضاشده را طی می‌کنند و فقط APK و AAB انتشار را در GitHub Releases می‌گذارند. فایل‌های Debug منتشرشده در Releaseهای قدیمی با این تغییر خودبه‌خود اصلاح یا جایگزین نمی‌شوند؛ از اجرای جدید خروجی بگیرید.

### انتشار APK آزمایشی در GitHub — بدون کلید خصوصی Release

در **Actions → Build Android APK → Run workflow** شاخهٔ حاوی این تغییرات را انتخاب کنید و `build_type` را روی **`github-test`** بگذارید (پیش‌فرض). این حالت بدون چهار Secret امضای Release اجرا می‌شود. گزینهٔ قدیمی `release` باید خاموش بماند؛ روشن بودن آن همیشه ساخت امضاشدهٔ فروشگاهی را انتخاب می‌کند. اگر فرم GitHub هنوز فقط گزینهٔ قدیمی `release` را نشان می‌دهد، تیک آن را بردارید تا روی همین شاخه حالت `github-test` اجرا شود:

1. برنامهٔ فعلی را با Node 22، JDK 21 و SDK 36 می‌سازد و APK استاندارد Debug تولید می‌کند.
2. امضای واقعی APK را با `apksigner` و نام بسته، نسخه، حداقل SDK و پرچم Debug را با `aapt` بررسی می‌کند.
3. APK را با نامی مانند `hesabyar-1.3.0-test.apk` و فایل `.sha256` ابتدا در یک Draft آپلود می‌کند؛ فقط پس از موفقیت آپلودها، آن را به‌صورت **Pre-release** عمومی می‌کند.
4. لینک دانلود مستقیم در خلاصهٔ اجرای Actions و بخش **Releases** قرار می‌گیرد. این انتشار `Latest` نمی‌شود و تگش با `android-test-v` آغاز می‌شود، نه تگ پایدار `v*`.

هر اجرای دوباره تگ جداگانه دارد تا APK با امضای احتمالی متفاوت جای فایل قبلی را نگیرد. **این فایل برای نصب روی گوشی است، نه انتشار در بازار یا سایر فروشگاه‌ها.** روی دستگاه واقعی به‌طور خودکار تست نمی‌شود.

اگر فقط فایل آزمایشی Actions را می‌خواهید و انتشار عمومی لازم نیست، **`test-apk`** را انتخاب کنید؛ Artifact با نام `hesabyar-android-debug-NOT-FOR-STORES` ذخیره می‌شود و GitHub Release ساخته نمی‌شود. هر دو نوع تست از امضای موقت استاندارد Debug استفاده می‌کنند، نه کلید خصوصی انتشار کاربر.

| `build_type`     | خروجی                                                               | نیازمند چهار Secret امضا |
| ---------------- | ------------------------------------------------------------------- | ------------------------ |
| `github-test`    | APK آزمایشی + SHA-256 در GitHub Pre-release                         | خیر                      |
| `test-apk`       | فقط Artifact آزمایشی Actions                                        | خیر                      |
| `signed-release` | Artifact دارای APK و AAB با امضای خصوصی، مناسب مسیر انتشار فروشگاهی | بله                      |

**تگ‌های `v*` همیشه مسیر `signed-release` را انتخاب می‌کنند**؛ حتی اگر ورودی دستی آزمایشی باشد. بدون Secrets معتبر، ساخت فروشگاهی خطا می‌دهد و به Debug برنمی‌گردد.

برای انتشار آزمایشی همین جلسه، push روی شاخهٔ `arena/da58321a-karenyar` فقط در صورت وجود نشانگر `[android-test]` در پیام کامیت، همین مسیر عمومی آزمایشی را خودکار اجرا می‌کند؛ pushهای عادی این شاخه خروجی عمومی تازه نمی‌سازند. این مسیر محدود به همین شاخه است و روی `main` یا تگ‌های `v*` اعمال نمی‌شود.

اگر دکمهٔ اجرای Actions از ابزار خارجی خطای دسترسی 403 می‌دهد، صاحب مخزن باید دسترسی GitHub را اصلاح کند یا خودش از صفحهٔ Actions این اجرای دستی را شروع کند. هیچ رمز یا توکن GitHub را در چت ارسال نکنید.

قبل از حذف نصب قبلی، از داخل برنامه خروجی JSON بگیرید؛ امضای Debug اجرای جدید ممکن است با نصب قبلی متفاوت باشد و حذف برنامه داده‌های محلی آن را پاک می‌کند.

## روش دوم: Android Studio، بدون GitHub Secrets

پیش‌نیازها: Node.js 22 یا بالاتر، Android Studio، JDK 21 و Android SDK 36.

```bash
npm ci
npm run android:sync
npm run android:open
```

در Android Studio:

1. **Build → Generate Signed App Bundle / APK** را باز کنید.
2. **APK** را انتخاب کنید.
3. Keystore انتشار خودتان، Alias و رمزها را وارد کنید؛ برای برنامهٔ قبلاً منتشرشده کلید تازه نسازید.
4. نوع ساخت **`release`** را انتخاب کنید و ساخت را پایان دهید.
5. فایل APK امضاشده را از پوشهٔ خروجی تعیین‌شده در همان پنجره بردارید، نه `app-debug.apk`.

از **Run** یا **Build APK** معمولی به‌عنوان جایگزین Generate Signed APK استفاده نکنید؛ آن مسیرها ممکن است نسخهٔ Debug بسازند.

## بررسی امضای APK روی سیستم خودتان

پس از ساخت، با مسیر واقعی فایل APK و پوشهٔ Build Tools نصب‌شده اجرا کنید:

```bash
npm run android:verify -- \
  android/app/build/outputs/apk/release/app-release.apk \
  "$ANDROID_HOME/build-tools/36.0.0"
```

اگر مسیر خروجی Android Studio متفاوت است، آرگومان اول را عوض کنید. در Windows نیز مسیر APK و پوشهٔ Build Tools را به‌صورت مسیرهای ویندوز و داخل کوتیشن بدهید.

این دستور از `apksigner verify` برای اعتبارسنجی امضا و نمایش مشخصات گواهی، و از `aapt dump badging` برای بررسی `debuggable` استفاده می‌کند؛ صرفاً به نام فایل اعتماد نمی‌کند. تست‌های خود ابزار، بدون نیاز به Android SDK، با دستور زیر اجرا می‌شوند:

```bash
npm run test:android-release
```

## نکات نسخه‌های بعدی و نصب روی گوشی تست

- شناسهٔ برنامه در این پروژه `ir.karensoft.hesabyar` است؛ برای به‌روزرسانی همان برنامه آن را عوض نکنید.
- در انتشارهای بعدی، `versionCode` در `android/app/build.gradle` باید از نسخهٔ قبلی فروشگاه بزرگ‌تر باشد؛ `versionName` را هم متناسب با نسخه تغییر دهید.
- همهٔ به‌روزرسانی‌ها را با همان کلید Release امضا کنید. Keystore و رمزها را جدا از مخزن، با نسخهٔ پشتیبان امن نگه دارید.
- نسخهٔ Release با امضای متفاوت روی نسخهٔ Debug نصب‌شده به‌صورت به‌روزرسانی نصب نمی‌شود. **قبل از حذف نسخهٔ آزمایشی از داده‌های برنامه پشتیبان بگیرید**؛ حذف برنامه می‌تواند داده‌های محلی آن را پاک کند.
- کلیدهای لایسنس آفلاین برنامه و Keystore امضای APK دو سازوکار مستقل‌اند. این راهنما فقط مشکل بستهٔ Debug و مسیر ساخت نسخهٔ انتشار را حل می‌کند؛ تأیید سایر الزامات فروشگاه جداست.
