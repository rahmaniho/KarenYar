# مهاجرت، پشتیبان‌گیری و rollback

## 1. نسخه‌ها

- IndexedDB برنامه: **v4** (قبلی v3)
- قالب پشتیبان‌گیری: **v3** (قبلی v2)

تغییرات افزایشی‌اند: جدول `financialEvents`، ایندکس‌های پرداخت، فیلدهای اختیاری پیش‌نویس/سند/قلم. هیچ جدول یا رکورد کاربری در مهاجرت حذف نمی‌شود.

## 2. پیش از استقرار

1. در نسخهٔ فعلی برنامه، از تنظیمات خروجی پشتیبان بگیرید.
2. فایل backup را بیرون از مرورگر/دستگاه نگه دارید.
3. اگر ممکن است، همان backup را روی staging وارد کنید و نسخهٔ جدید را آنجا باز کنید.
4. پس از باز شدن نسخهٔ جدید، یک backup v3 جدید هم بگیرید.

## 3. مهاجرت v3→v4

- Dexie هنگام باز شدن برنامه مهاجرت را اجرا می‌کند.
- پرداخت‌های قدیمی بدون `paymentKey` حفظ می‌شوند.
- جدول `financialEvents` خالی ایجاد می‌شود.
- فیلدهای جدید اختیاری‌اند و اسناد قدیمی را نمی‌شکنند.
- اگر مهاجرت خطا دهد، برنامه نباید دادهٔ قبلی را پاک کند؛ خطا را گزارش و از backup قبل از مهاجرت استفاده کنید.

آزمون‌های `migration.test.ts` و `backup.test.ts` این مسیر را پوشش می‌دهند.

## 4. وارد کردن backup

- backup v3 قبل از import اعتبارسنجی می‌شود: فاکتور/قلم/پرداخت/درآمد/رویداد نباید یتیم باشند؛ کلید پرداخت تکراری رد می‌شود.
- import اتمی است؛ اگر خطا رخ دهد، تغییرات ناقص اعمال نمی‌شود.
- backup v2 قدیمی همچنان قابل وارد کردن است و به ساختار جدید نگاشت می‌شود.
- backup v3 را نمی‌توان در نسخهٔ قدیمی برنامه که فقط v2 را می‌شناسد وارد کرد.

## 5. Rollback

### حالت امن: قبل از تولید دادهٔ جدید

1. کد/استقرار قبلی را برگردانید.
2. backup گرفته‌شده **قبل از مهاجرت** را در نسخهٔ قبلی وارد کنید.
3. صحت موجودی، درآمد و دریافتنی‌ها را با چند سند نمونه کنترل کنید.

### حالت خطر: بعد از ثبت داده در v4

- downgrade خودکار v4→v3 ارائه نشده است.
- اگر به کد قدیمی برگردید و backup قدیمی را وارد کنید، اسناد/پرداخت‌های ثبت‌شده بعد از مهاجرت از دست می‌روند.
- پیش از rollback، از وضعیت v4 خروجی backup بگیرید و داده‌های جدید را جداگانه مستند/استخراج کنید.
- توصیه می‌شود به‌جای rollback فوری، مشکل را در نسخهٔ جدید اصلاح کنید (forward fix)، مگر اینکهپشتیبان قبل از مهاجرت موجود و دادهٔ جدید قابل چشم‌پوشی باشد.

## 6. چک‌لیست پس از استقرار

- [ ] برنامه بدون خطای کنسول باز می‌شود.
- [ ] یک پیش‌نویس ساخته و ویرایش می‌شود.
- [ ] یک فاکتور نسیه صادر و دریافت جزئی ثبت می‌شود.
- [ ] چاپ/PDF وضعیت و مبالغ درست را نشان می‌دهد.
- [ ] خروجی backup v3 گرفته و روی staging دوباره وارد می‌شود.
- [ ] دادهٔ نمایشی در build عملیاتی تولید نمی‌شود.
- [ ] موجودی و درآمد یک فروش آزمایشی با گردش انبار/دفتر درآمد مطابقت دارد.

## 7. دستورات ساخت

```bash
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

خروجی build در `dist/` است. PWA precache تولید می‌شود. پس از استقرار، کش مرورگر/PWA ممکن است نسخهٔ قدیمی را نگه دارد؛ یک بار reload سخت یا بستن/باز کردن PWA توصیه می‌شود.
